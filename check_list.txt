[ ] 3.1. Xây dựng Knowledge Base (Memory):
[ ] Định nghĩa lại cấu trúc Rule cho Semantic Search:

JSON

  "condition_description": "Mô tả ngữ cảnh user (dùng để so khớp vector)",

  "created_at": "timestamp",
  "performance_score": 0.5 (để đánh giá rule này tốt hay xấu sau này)
}
[ ] 3.2. Agent 3: The Retriever (Module tìm kiếm):

[ ] Viết hàm retrieve_rules(user_context) (Thay thế Keyword Matching ):

B1: Vector hóa user_context hiện tại.

B2: Tính Cosine Similarity với vector của các Rules trong KB.

B3: Lấy Top-K rules có điểm tương đồng cao nhất (> ngưỡng threshold).Output: List các instruction phù hợp.

[ ] 3.3. Agent 1: The Optimizer (Module gợi ý):

[ ] Viết hàm build_prompt(user_profile, retrieved_rules):

Template ghép nối: [Vai trò] + [Dữ liệu User] + [Rules bắt buộc áp dụng] + [Yêu cầu Output JSON].

[ ] 3.4. Agent 2: The Analyst:
[ ] Input Prompt bổ sung: applied_rules (Các rule mà Agent 1 đã kích hoạt).
 [ ] Logic phân tích: * Nếu applied_rules rỗng -> Lỗi do thiếu kiến thức -> Tạo Rule mới. * Nếu applied_rules có -> Lỗi do Rule sai hoặc Rule chưa đủ mạnh -> Sửa/Gộp Rule.
GIAI ĐOẠN 4: EVALUATION & FEEDBACK LOOP (Vòng lặp tự học)

[ ] 4.2. Xây dựng hàm update_knowledge_base (Feedback Loop):

[ ] Input: List các lỗi (self.error_list từ Eval).

[ ] Logic:

Chọn ra top N lỗi điển hình.

Gửi cho Agent 2 phân tích -> Đề xuất Rule mới/Sửa Rule cũ.

[ ] (Mới) Logic "Consolidation & Pruning" (Quan trọng):

Trước khi lưu Rule mới, kiểm tra sự mâu thuẫn với Rules cũ.

Nếu Rule mới bao trùm Rule cũ -> Xóa Rule cũ, giữ Rule mới.

Nếu Rule mới mâu thuẫn -> Dùng Agent 2 để quyết định giữ cái nào (hoặc gộp lại).
